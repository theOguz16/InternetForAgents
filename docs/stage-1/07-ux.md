# Kullanıcı yolculukları ve frontend mimarisi

## Bilgi mimarisi

Keşfet → Agent detayı → Doğrudan görev; İş akışları → Görev oluştur → Görev detayı → Geçmiş. Geliştirici: Agent’larım → Kaydet/Doğrula → Yayınla/Güncelle/Askıya al. Operatör: Sistem durumu → Olay/kota/ağ politikası. Aynı kullanıcı developer olabilir; her eylem server tarafında yetkilendirilir.

| Ekran | Ana alanlar | Boş/hata/erişim durumu |
| --- | --- | --- |
| Keşfet | Arama, beceri/sürüm, kayıt durumu, veri zamanı | Sonuç yok, doğrulanamayan kayıt, Registry hatası ayrı |
| Agent detayı | Owner, skill, schema, örnek, sürüm, mod, last verified | Yetkisiz içerik gizli; beyan ile gözlem ayrı |
| Agent’larım | Kayıt formu, revision, validation raporu | Çakışan update için yeniden yükleme; secret field yok |
| Doğrudan görev | Schema’dan form, örnek yükleme, bütçe | Unsupported schema açık; ham JSON alternatif validasyonu |
| Workflow | Adımlar, FunctionSpec, girdiler, seçilecek profiller | Eksik girdi ve bağımlılık daha submit edilmeden açıklanır |
| Görev detayı | Adım grafiği/listesi, durum, sağlayıcı, gerekçe, artifact | Partial ve unknown görünür; tekrar/iptal yeteneğe göre |
| Geçmiş | Owner job’ları, filtre, tarih, durum | Sayfalama ve retention bilgisi |
| Operasyon | Latency/hata/kuyruk/limit | Ham kullanıcı context’i varsayılan gösterilmez |

## Akış 1: geliştirici onboarding

Şablonu indir → handler/model adapter yaz → yerel uyum kontrolü → ayrı container aç → cardUrl/manifestUrl kaydet → validation raporunu düzelt → active kayıt → sentetik görev gönder. Geliştiriciye endpoint’in tarayıcıdan değil Registry/Orchestrator ağından erişilebilir olması gerektiği anlatılır. Manifest yüklemek keyfî kodu platforma deploy etmek değildir.

## Akış 2: kullanıcı

Akış veya beceri seç → yapılandırılmış girdi doldur → mode/bütçe gör → gönder → queued/working/terminal durumlarını izle → sonucu ve kaynakları incele. 'Test üretildi' ve 'Test geçti' farklı kartlardır. fixture sonuç sarı/etiketli ve metinle açıklıdır; yalnız renge dayanılmaz.

## Akış 3: kopma ve yeniden açılma

Ağ kopması banner’ı görev başarısızlığına dönüştürülmez. UI aynı job ID’ye yeniden bağlanır; yeni POST yapmaz. Aynı içerik retry anahtarı korunur; belirsiz submit sonrası kullanıcı yeni iş oluşturacağını bilmeden duplicate yaratamaz. Yeni iş düğmesi açıkça yeni idempotency anahtarı üretir. Reload restore, terminal stream kapanışı, timeout ve auth expiry ayrı senaryolardır.

## Ekran taslağı

```text
[Keşfet] [İş akışları] [Görevlerim] [Agent’larım]
Görev adı                        [Durum] [Yetkili eylemler]
Girdi özeti / bütçe / başlangıç
[Üretim] ── [Review]
        └── [Test üretimi] ── [Çalıştırma]
Seçilen adım: sağlayıcı / sürüm / seçim nedeni / süre
[Sonuç] [Kod] [Test raporu] [Teknik olaylar]
```

## Frontend katmanları

React/Vite. features/discovery, registration, job-create, job-detail, artifacts, developer-tools. shared/api, events, ui. REST client response validation yapar; SSE aboneliği tek hook/service’e ayrılır. UI local state ile server state ayrılır. Sahiplik ve seçici backend’de kalır. İlk sürümde ayrı global state framework zorunlu değildir; işlevsel gereksinim oluşmadan eklenmez.

Same-origin Platform API; API reverse-proxy hedefi kullanıcı tarafından seçilemez. Raw artifact HTML olarak render edilmez. Kod metin olarak gösterilir; indirme yetkili ve boyutu sınırlıdır. Büyük sonuçlarda DOM sanallaştırma ihtiyacı ölçülür; sınırsız log append edilmez.

## Kullanılabilirlik kabulü

360 px ve 1280 px genişlikte temel akış; yatay taşma yalnız kod alanında kontrollü. Klavye ile kayıt/görev/sonuç; görünür focus; label ve hata ilişkisi; ekran okuyucuda throttled durum bildirimi, her token’da duyuru yok. Bağlantı durumu kalıcı ve anlaşılır. Disabled eylemin nedeni görünür. Beş ekip üyesiyle görev tamamlama ve destek ihtiyacı kaydedilir; küçük örneklemi genelleme yapılmaz.

G01 tasarım teslimidir. Mevcut tek sayfa demo bu ekranların tamamını uygulamıyor. G02–G08 implementasyon ve tarayıcı testleridir.
